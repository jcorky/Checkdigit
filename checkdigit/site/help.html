Using CHECKDIGIT

Everything on this page applies to the app at app.thecheckdigit.com — and to any self-hosted copy.

Quick start

  1. Open the app and add your file

    Drop a file on the Correct tab, or paste raw text straight into the box. Files up to 5 MB are accepted; the format is detected from the content, never the file name.

  2. Review what was found

    Every equipment identifier is listed with a verdict (see below) and, where a check digit was wrong, the exact before → after change.

  3. Download the corrected file

    You get the file back in its original format. It differs from your input only at the check-digit characters that were wrong — nothing else is rewritten, re-encoded, or reflowed.

Just checking one number? The box on the front page validates a single container number instantly, and The math shows the full calculation step by step.

What the verdicts mean

CHECKDIGIT only corrects when the context justifies it. Anything ambiguous is surfaced for you instead of silently rewritten.

VALID

The check digit is already correct. Nothing to do.

CORRECTED

The check digit was wrong and the number sat in a field that is declared to carry an equipment ID (EDIFACT EQD, X12 N7, an SNX equipment attribute, a recognised column…). The correct digit was computed and spliced in.

FLAGGED

The number fails its check, but the context doesn't justify a silent fix — it appeared in free text, its identifier type is ambiguous, or an owner-prefix policy applies. It's listed for your review with the suggested digit.

INVALID

The token doesn't have the shape of any supported identifier (for a container: 4 letters, 6 digits, 1 check digit). It can't be validated, so it's reported as-is.

Why was my number flagged instead of corrected? Usually because it was found in free text rather than a declared equipment field. Correcting a "number" that might be a booking reference or a phone digit run would corrupt your data — so CHECKDIGIT asks instead of guessing.

Formats & identifiers

Detection is structural — a BAPLIE renamed to .txt is still recognised as a BAPLIE.

EDIFACTANSI X12SNX XML CSV / TSVFixed-widthXLSX Plain text
  • ISO 6346Maritime containers — mod-11 check digit, recomputed and corrected. See the calculation.
  • ILU · EN 13044Intermodal loading units (categories A/B/D/E/K), routed to their own category set.
  • UIC wagon12-digit rail wagon numbers — a different scheme (Luhn mod-10), never cross-applied.
  • Size / typeCodes like 22G1 or 45R1 are decoded for context and deliberately never altered.

Public vs. admin

Uploading and correcting is open to everyone — no account, no sign-in. The Dashboard, History, Containers and Policy tabs read the audit warehouse and are restricted to the administrator: they appear after a Google sign-in, and the server rejects any account that isn't on the allow-list. Hiding the tabs is cosmetic; the server-side check is the actual boundary.

Privacy

Every processing run is logged so the operator can audit throughput: file name, detected format, size, timestamp, browser user-agent, and the verdict counts. Your IP address is never stored — the audit schema has no column for it.

On the hosted instance, traffic passes through a CDN edge that terminates TLS, so operational data in your files transits that provider. If your manifests are sensitive, self-host — the whole point of CHECKDIGIT is that you can run it entirely on your own hardware.

Owner/box enrichment lookups are opt-in and switched off by default; nothing calls out to an external source until the operator configures one.

Self-hosting

CHECKDIGIT ships as a small FastAPI + SQLite service with a stdlib-only correction core. From the distribution folder:

  • One command./bootstrap.sh — installs system packages on Debian/Ubuntu/Mint and builds everything. Add --run to start on 127.0.0.1:8000, or --verify to run the full test suite.
  • Dockerdocker compose -f docker-compose.public.yml up -d --build — the public stack: app, Caddy, Cloudflare Tunnel, Litestream backups. See DEPLOY_PUBLIC.md in the distribution.
  • Verify it./smoke-test.sh checks a running deployment from the outside: public surface answering, admin locked, Swagger off.

FAQ

Will it change anything else in my file?

No. Corrections are applied by byte splice: the file is parsed to find each identifier's exact byte offset, and only the check-digit character is replaced. Delimiters, encoding, padding, line endings and every untouched field stay byte-for-byte identical — and each splice is verified before the file is returned.

What's the maximum file size?

5 MB per upload. Larger files are rejected with a clear error (and the rejection is logged, like every run).

Can it fix a wagon number with the container algorithm?

Never. Each identifier type is routed to its own scheme — ISO 6346 mod-11 for containers and ILU units, Luhn mod-10 for UIC wagons. If the type is ambiguous, the number is flagged rather than guessed at.

Why does the corrected XLSX open identically in Excel?

The workbook is rebuilt preserving the original member bytes wherever they weren't touched, so styles, formulas and layout survive. Only cells containing a wrong check digit change.

Where does the "owner" information come from?

The BIC register is the authoritative source for owner prefixes. Enrichment is off until the operator loads it; note that a leasing company's prefix on a box says who owns it, not who is operating the shipment.

Something looks wrong — how do I dig in?

Use the front-page checker or the step-by-step calculation to verify a single number by hand. Self-hosters can run ./smoke-test.sh against their instance and python3 run_acceptance.py against the code.
