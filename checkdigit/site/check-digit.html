How the check digit is calculated

Every container number carries one self-verifying character — the 11th. It's computed from the first ten by a fixed recipe: map each character to a number, weight it, sum, take mod 11. This page walks the whole calculation, live.

Step 1 — every character becomes a number

Digits keep their value (0–9). Letters are numbered from A = 10 upward — but every multiple of 11 is skipped (11, 22, 33), so no letter's value collides with the modulus. That's why L is 23, not 22, and V is 34, not 33.

Step 2 — each position gets a doubling weight

Position 1 is worth ×1, and each next position doubles: 2⁰ through 2⁹. Because position changes the weight, swapping two different characters usually changes the total — which is what lets the digit catch transpositions.

Step 3 — sum, mod 11, and the special case

Multiply each value by its weight, add the ten products, and take the remainder mod 11. That remainder is the check digit — with one exception: a remainder of 10 becomes 0, because the check digit must be a single character.

The remainder-10 case. Because 10 → 0, a check digit of 0 stands for two different remainders. The standard's guidance is for owners to avoid issuing serials whose remainder is 10; such numbers still validate (check digit 0), and CHECKDIGIT's kernel notes the remainder-ten case explicitly when it sees one.

Try it — the full calculation, live

Type any container number. Ten characters compute the check digit; an eleventh is verified against it. It loads with the ISO 6346 example, CSQU3054383.

Same math as the engine. This page runs the identical algorithm as the correction kernel in the app — the acceptance suite verifies them against each other vector-for-vector, so what you see here is exactly what the app computes.

What it catches — honestly. Almost every single-character mistake and most adjacent transpositions change the sum mod 11, so the digit fails and the error is caught. The known blind spot: two characters whose values differ by a multiple of 11 contribute identically — for example the digit 1 (value 1) and the letter B (value 12) — so that particular substitution slips through. No single check character can catch everything; this scheme catches the mistakes people actually make at gates and keyboards.

And for other equipment?

ILU codes (EN 13044, categories A/B/D/E/K) use this same arithmetic with their own category letters. UIC wagon numbers are a different scheme entirely — 12 digits with a Luhn mod-10 check — which is why CHECKDIGIT routes every identifier to the algorithm its own standard defines and never cross-applies this one.
